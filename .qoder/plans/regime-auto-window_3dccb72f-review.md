# regime-auto-window 计划评审（投研顾问视角）

> 评审对象：`.qoder/plans/regime-auto-window_3dccb72f.md`
> 评审日期：2026-09-03
> 结论：工程回归保护（PIT 隔离、无换挡股逐点一致、逃生阀保留）扎实，但存在两个执行断层（P0）与两类方向性信号偏差（P1），需修订后再实施。

---

## 阻断级问题（执行后目标落空或直接出错）

### D1. param_source 恢复机制会劫持自动检测，紫金根本轮不到自动窗口

`build_report.py` L103-108 的恢复逻辑：`_ps.get('pe') in ('manual', 'calibrated')` 时把旧 JSON 的区间恢复为 `args.pe`。紫金旧 JSON 的 `param_source.pe = 'calibrated'`（由 MANUAL_RANGES 生成）。

计划 T4 保留 calibrated 兼容读取 → 批量重跑时旧区间 PE 8.3~18 被恢复 → `use_rank_pe=False` → 仍走线性映射。**检测函数照常标注 window_start，但评分链路完全不用它**。

T5 的验证（紫金仍偏贵低分）会通过——通过原因是恢复机制屏蔽了新机制，形成假阳性。计划缺少一步旧 JSON 迁移（清除三只股票的 calibrated 区间恢复源），保留兼容读取与 MANUAL_RANGES 退役两个目标直接冲突。

### D2. detect_regime_window 的输入契约在 T3 调用点破裂

T1 要求输入 `{year: eps}`，但 T3 调用处传入的 `_eps_series`（`report_generator.py` L216）在 adj_series 存在时是 **`{date: value}` 逐日键**（见 `financial_fetcher.py` L592 `build_adjusted_series` 返回结构）。直接传入，年份分段逻辑会对 `'2021-05-06'` 这类日期串做分段运算，整体错乱。

即便补一个降采样步骤，还有一个隐藏偏移：生效年规则是 T 年年报次年 5 月生效（`_series_effective`），取某年 12 月 31 日的逐日值对应的是**上一年年报的 EPS**，年份映射需再偏移校正。计划对这个关键转换零字。

### D3. regime_unstable 双处判定口径不一致

T2 在引擎内按排序数组样本数判（仅收集 PE>0 的日子），T3 在 report_generator 按 kline 行数判。亏损日、缺 EPS 日在引擎侧被剔除、报告侧被计入，边界处会出现 meta 标注 unstable 但评分未中性化（或反向）的矛盾。应单点判定（引擎返回，报告层只读）。

## 方向级问题（信号在最需要正确的位置系统性出错）

### A1. 对称触发条件把周期回落当成换挡 → 周期底部给出最差评分

比值 <0.5 同样记换挡点，窗口切到最近段。神火、云铝本身就是周期股：2021 暴利 + 2023-2025 回落，当前窗口内盈利回落段 EPS 压缩快于股价，PE 分位系统性偏高 → 低分 → **高估信号恰好出现在周期底部（最该买入的位置）**。

这与已有教训同构（记忆：估值模型区间锚定失真，regime 切换需二次确认与校准）。原 8.4c 规则是人工判断语境下的辅助手段，机械推广到全市场后，往返摆动和单向质变没有区分。向下换挡至少需要二次确认，或对 cyclical 模型禁用向下触发。

### A2. 上行跃迁股在景气顶部会系统性显得便宜

窗口本身是被盈利趋势选出来的趋势段：光模块/存储股（中际旭创、新易盛、德明利、香农芯创）盈利兑现期 EPS 增速持续高于股价增速，窗口内 PE 分布单调压缩，当前 PE 分位天然偏低 → 高分。

汇总筛选表的顶部将系统性聚集处于景气顶部的股票——这正是估值系统最初要识别的周期股 PE 陷阱，换窗口后换了个形态回来。计划风险 1 只把它当窗口过短处理（调 REGIME_RATIO），没有识别出这是方向性偏差而非参数问题。

### A3. REGIME_RATIO=2.0 等价于年化复合 15% 即触发

5 年段中位数比值 2.0 = 复合年化 15%。这个门槛下正常成长路径（15% 复合）被判为盈利质变，计划用例 C 本身就演示了持续触发。触发率 >30% 才调参的规则等于把已知偏低的阈值先带上生产。阈值至少 3.0（年化 25%）起步，或者改用增速语义而非段间比值。

### A4. 亏损段跳过 = 最典型的失真案例不在覆盖范围内

计划要根治的是低 EPS 历史污染区间，而中远海控模式（亏损 → 暴利 → 常态，此前 74% 交易日误判高估）恰好全程经过亏损段 → `loss_period_skip` → 全历史 → 污染照旧。

计划宣称根治，实际只覆盖单向上行跃迁一类。且 T5 对照名单里没有中远海控。亏损段的可选处理：剔除亏损段、用两侧正常段比较——直接放弃检测是最保守的选择，但至少应在 HTML 对这类股票显式降权警示，而非仅靠 window_reason 字段。

### A5. PE 与 PB 捆绑窗口化，PB 被过度处理

盈利换挡冲击的是 PE 锚；只要 BPS 序列连续，PB 锚仍然有效（BPS 断裂已有正交处理机制）。现有的人工校准也是分开定的（宝丰 PE 8-20、PB 1.5-5）。

T2 把 pb 排序数组与 pe 一起过滤、窗口不足 50 日时一起中性 50 分——刚换挡的股票丢掉了唯一仍可用的估值锚。PB 应跟随独立的 BPS 断裂检测决定窗口。

### A6. 检测输入用报表 EPS 而非扣非

跨年计提的减值、一次性处置收益会拖动段中位数，制造伪换挡。判断盈利质变，投研标准输入是扣非净利或经营性盈利趋势。数据源拿不到就应在风险表里承认这项噪声，目前没有。

## 设计细节问题

- **B1 分段对齐任意**：段边界锚定序列首年，数据起点差 1-2 年，换挡点可差数年；换挡点粒度是段边界而非实际跃迁年，窗口可以比真实质变晚 1-4 年，旧 regime 数据继续入窗。尾部不满 5 年的段丢弃还是保留未定义——丢弃则最近一次跃迁检测不到，保留则中位数不稳。
- **B2 窗口头部的口径缝隙**：`date >= f'{year}-01-01'` 切窗，但该年年报次年 4-5 月才生效（`_series_effective` 规则），窗口头部数月仍是旧盈利定价的 PE，与全系统 Point-in-Time 严谨性不一致。影响小，但与既有口径的自洽性被打断。

## 验证设计问题

- **C1 循环论证**：T5 用紫金应仍偏贵低分（对照 8.4c）做验收。8.4c 人工锚是线性映射 24.37 分，新方法是窗口内 rank 分位，两套估值观，新分数落点完全取决于窗口起点。不一致时计划只说暂停检查参数，没有判据区分是检测错还是人工锚本来就错。
- **C2 对照组结构缺失**：四只全是上行跃迁股。缺三类关键 case：向下换挡（周期回落）、亏损段（中远海控、宏达）、高增长伪触发（光模块/存储任选 2-3 只）。触发质量没有 ground truth——应人工标注每只触发股是真跃迁还是周期波动，再谈触发率阈值。

## 修订建议（按优先级）

| 优先级 | 修改 |
|---|---|
| P0 | T4 增加旧 JSON 迁移：清除三只校准股的 calibrated 区间恢复源（或恢复白名单对 pe/pb 不再认 calibrated），否则目标落空 |
| P0 | T1 明确输入契约：从 adj_series 逐日序列降采样的取值时点、生效年报年映射规则，并加对应测试用例 |
| P1 | 向下换挡二次确认或对 cyclical 禁用；REGIME_RATIO 起步 3.0 |
| P1 | PB 独立窗口（跟随 BPS 检测），窗口不足时只中性化 PE |
| P2 | 对照组补中远海控 + 2-3 只光模块/存储，人工标注触发清单真伪后再定参数 |
| P2 | regime_unstable 改为引擎单点返回 |

## 总评

工程上的回归保护（PIT 隔离、无换挡股逐点一致、逃生阀保留）做得扎实，但方案的核心风险在投研逻辑侧——它假设换挡后的窗口是有效的估值锚，对向上跃迁成立，对周期回落和景气顶部两类场景会系统性给出反向信号，而四只校准股当前恰恰都处在或临近这两类场景。先解决 D1/D2 两个执行断层，再对 A1/A2 的方向性偏差做出设计回应（而非留到触发清单里人工复核），这份计划才具备落地条件。
